Saves the state of a Proxmox VE cluster (configuration, resources, audit data) at a point in time in a single file to download. Use it for compliance audits, customer hand-over, change tracking and capacity planning. It is built on the [`cv4pve-report`](https://github.com/Corsinvest/cv4pve-report) library.

## Sections

- **Overview**: introduction to the module
- **Reports**: history of the generated reports with id, start, duration and format. See [Reports](#reports)

## Reports

| Action | What it does |
|--------|--------------|
| **New** | Opens the **New Report** panel: choose the format and the content (see [Report options](#report-options)), then save to start the generation in the background |
| **Download** | Downloads the selected report as a `.zip` file. Disabled until the report is finished |
| **Delete** | After confirmation, deletes the selected report and its file |
| **Refresh** | Reloads the grid |

Click the **Id** of a row to open, read-only, the options the report was generated with. Progress and log of a running report are in the global Task Tracker.

Reports are generated on demand only: the module has no schedule and no retention, so old reports stay until you delete them.

## Report options

The **Fast**, **Standard** and **Full** buttons at the top of the panel load a ready-made set of values. The tables below show the **Standard** values. A new report starts with **Fast**.

### General

| Option | Standard | Purpose |
|--------|----------|---------|
| **Format** | Xlsx | `Xlsx`, `Html` or `Json` |
| **Max Parallel Requests** | 5 | Max parallel requests when fetching data (1 = sequential) |
| **API timeout (seconds)** | 0 | API timeout in seconds (0 = use the default) |

### Cluster

| Option | Standard | Purpose |
|--------|----------|---------|
| **Include** | on | Cluster overview |
| **Tasks** | on | Cluster tasks |
| **Audit Log** | off | Cluster log, with **Max Count** (0 = unlimited) |

### Node

| Option | Standard | Purpose |
|--------|----------|---------|
| **Names** | `@all` | Nodes to include |
| **RRD Data** | on | Node metrics, with **Time frame** (`Hour`, `Day`, `Week`, `Month` or `Year`; default Day) and **Consolidation** (default Average) |
| **Syslog** | off | Node syslog, with **Max Count** (default 500, ignored when the period has a start date) and **Period** (a single date range field) |
| **Replication** | on | Replication jobs |
| **Node Detail** | on | Enables the options below |
| **APT** | on | Available APT updates |
| **Disk Detail** | on | Disk details |
| **S.M.A.R.T. Data** | off | S.M.A.R.T. attributes of the disks |
| **Firewall Log** | on | Node firewall log |
| **Tasks** | on | Node tasks, with **Only Errors** (off), **Max Count** (0 = unlimited) and **Source** (`all`, `local` or `active`; default `all`) |

### Guest (VM / CT)

| Option | Standard | Purpose |
|--------|----------|---------|
| **IDs** | `@all` | Guests to include |
| **RRD Data** | off | Guest metrics, with **Time frame** and **Consolidation** |
| **Snapshots** | on | Snapshots of each guest |
| **Disks** | on | Disks of each guest |
| **Partitions** | on | Partitions of each guest |
| **QEMU Agent** | on | Data read through the QEMU Guest Agent, with **Agent Timeout sec.** (default 3) |
| **Guest Detail** | on | Enables **Firewall Log** (on) and **Tasks** (on, same options as the node tasks) |

### Storage

| Option | Standard | Purpose |
|--------|----------|---------|
| **Content** | on | Storage content |
| **Backups** | on | Backups on the storage |
| **RRD Data** | on | Storage metrics, with **Time frame** and **Consolidation** |

### Firewall

| Option | Standard | Purpose |
|--------|----------|---------|
| **Firewall** | on | Firewall rules, aliases, ipsets and log, with **Max Count** (0 = unlimited) and **Period** (a single date range field) for the log |

### Capacity Planning

| Option | Standard | Purpose |
|--------|----------|---------|
| **Capacity Planning** | off | Average and peak usage of guests and nodes, storage growth and days to full. Each table needs the **RRD Data** of its section (Node, Guest, Storage) and uses its time frame |

## Settings

The module has no settings at module level: everything is chosen per report in [Report options](#report-options).

## Widgets

| Widget | Content |
|--------|---------|
| **Daily Status** <Tag kind="ee" /> | Successful and failed reports per day (last 14 days) |

## Permissions

Assign these to a role under [Security](../../configuration/admin-area/security/#permissions).

| Permission | Allows |
|------------|--------|
| **System Report** | Open the module and its **Overview** page |
| **Reports** | Open the page with that name (one permission per page) |
| **Report: Create / Delete** | Start a **New** report, delete a report |
| **Report: Download** | Download a report |
| **Daily Status** <Tag kind="ee" /> | Use the dashboard widget |

The built-in role of the module includes all of them. A custom role has to be given them explicitly: without the permission the button is hidden.
