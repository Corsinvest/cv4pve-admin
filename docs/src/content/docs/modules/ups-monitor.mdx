## Sections

- **Overview**: short description of the module
- **Dashboard**: one status card for each enabled UPS device
- **Devices**: UPS device configuration, on-demand scan, connection test and reading history
- **Trends**: charts of the readings over time

Devices, readings and settings are separate for each cluster.

:::caution[Monitoring and alerts only]
The module reads the UPS and sends notifications. It does not shut down or stop nodes, VMs or containers: the settings named **Shutdown ... Threshold** are alert thresholds.
:::

## Requirements

- The UPS (or its network card) must answer **SNMP v2c** queries from the cv4pve-admin server on the configured port (default UDP 161) with the configured community.
- **Host** must be an IP address.
- A request that gets no answer within 3 seconds is treated as a failed reading.

## Dashboard

Each enabled device has a card with:

- name, detected brand, status badge, manufacturer and model, location
- **Battery** gauge: red up to 20%, yellow up to 50%, green above
- **Load** gauge: green below 50%, yellow from 50%, red from 80%
- **Input Voltage**, **Runtime** (minutes), **Temperature** and **Last Scan**

The cards show the last reading and are updated when a scan ends.

### Status values

| Status | Meaning |
|--------|---------|
| **Online** | Output supplied by mains power |
| **On Battery** | Output supplied by the battery, charge above the shutdown battery threshold |
| **Low Battery** | The UPS reports a low battery while not running on battery |
| **Critical** | The UPS reports a depleted battery. Or it runs on battery and either reports a low battery or has a charge at or below the shutdown battery threshold |
| **Offline** | The last scan got no reading from the device: it did not answer, its name could not be resolved, or it has none of the values of the selected profile. The reading history shows the reason |
| **Unknown** | The device answered but its state is none of the above, for example bypass or voltage regulation active |

## Devices

The grid lists the devices of the cluster with **Enabled**, **Name**, **Host**, **Port**, **Connection**, **Detected Brand**, **Last Status**, **Last Scan**, **Location** and **Managed Nodes** (**All** or the number of nodes). Click the name of a device to edit it.

Each UPS device is configured with:

| Field | Description |
|-------|-------------|
| **Enabled** | Include the device in the scheduled scan and in the Dashboard (default: on) |
| **Name** | Friendly name for the UPS device (required) |
| **Host** | IP address or host name of the UPS SNMP agent (required) |
| **Port** | SNMP port (default: 161) |
| **Community** | SNMP v2c community string (default: `public`) |
| **Profile** | SNMP device profile (`auto` = detect the brand from the device, or pick one explicitly) |
| **Location** | Physical location label |
| **Description** | Free-text notes |
| **Managed Nodes** | Proxmox nodes powered by this UPS (empty = all nodes): informational |
| **Identification** | Manufacturer, Model, Firmware Version, Serial Number: filled from the device with **Retrieve Info**, or typed by hand |

**Retrieve Info** reads the identification values from the device with the selected profile and writes them in the four fields. It needs the **Host** to be filled in. The values are saved with the device.

Per-device actions (select a row first):

- **Scan**: queues an immediate scan of the selected device. The result appears in the grid and in the reading history when the scan ends
- **Test Connection**: queries the device. When it answers, a dialog shows the SNMP system description the device declares, the profile used and one row for each value of the profile: where it is read from and the value received, or **Missing** when the device does not have it. The power source and the battery state are shown with their meaning next to the number. A warning says which alert thresholds cannot fire because the device has no charge or no runtime value. When the device does not answer, a message gives the reason: no answer within 3 seconds, or a host name that cannot be resolved. A missing answer usually means a wrong address, port or community, or SNMP v2c turned off on the device

### Profiles

With `auto` the profile is chosen at every scan by asking the device which values it has, and shown in **Detected Brand**:

1. the profile of the manufacturer the device declares (its SNMP object identifier), when the device has the values of that brand;
2. otherwise **Generic RFC 1628**, the standard UPS MIB, when the device has it. It is the case of most third-party SNMP cards;
3. otherwise any other verified brand whose values the device has.

The text of the system description is not used: it is written by the SNMP card and often names no brand. When the device answers but has none of these values, the scan and **Test Connection** fail with a message saying so: the device is not a UPS, or its SNMP card does not publish the values.

With a profile picked explicitly, a device that has none of its main values (battery status, charge, output source) fails the scan with a message that says the profile is probably the wrong one.

A verified profile is written from the published definitions (MIB) of the standard or of the manufacturer: every value, its unit and the meaning of each state. Verified profiles have been tried against a simulator, not on a real device of each brand: if the readings look wrong, run **Test Connection** and compare the values with the display of the device, or select **Generic RFC 1628**.

| Profile | Source | Notes |
|---|---|---|
| **Generic RFC 1628** | Standard UPS MIB | The standard has no serial number |
| **APC / Schneider Electric** | PowerNet MIB | Self-test, boost, trim, ECO and standby states count as on mains. No manufacturer value |
| **CyberPower** | CPS MIB | No manufacturer value |
| **Delta** | DeltaUPS MIB | No serial number |
| **Eaton / Powerware** | XUPS MIB | No battery-low state and no serial number |
| **HPE / HP** | CPQPOWER MIB | No battery-low state and no serial number. The MIB does not give the unit of the battery voltage: tenths of volt are assumed |
| **Mach Power / NetAgent / Ablerex / Tecnoware** | XPPC MIB (NetAgent cards) | No manufacturer value, no output power |
| **MGE / Pulsar** | MG-SNMP-UPS MIB | The MIB says "on battery: yes or no": bypass is not told apart from mains. The MIB gives no units: tenths of volt and of hertz, runtime in seconds are assumed |
| **Riello** | RIELLOUPS MIB | Same structure as the standard. The MIB gives no units: those of the standard are assumed. No serial number |
| **Tripp Lite** | TRIPPLITE-PRODUCTS MIB | Reads the first device of the card |

A value the brand does not define is read from the standard MIB, when the device has it.

These profiles are **not verified**: `auto` never chooses them, they work only when picked by hand, and the editor shows a note when one is selected.

| Profile | State |
|---|---|
| **Socomec** | Values taken from the Network UPS Tools driver for Net Vision cards, not from a Socomec MIB. Only the mains state is known: on battery the status is **Unknown** |
| **Huawei** | Values taken from the Network UPS Tools driver, not from a Huawei MIB |
| **Chloride**, **GE / General Electric**, **Phoenix Contact** | No definition found to check them against |

A brand that is not in the lists is read with **Generic RFC 1628**, which most network cards publish. A device saved with a profile that is no longer in the lists is read as `auto`.

A state of the device that is neither mains nor battery (bypass, output off, a state the profile does not know) gives the status **Unknown** and no alert.

### Reading history

Expand a device row to see its readings, newest first: **Timestamp**, **Status**, **Battery (%)**, **Input (V)**, **Load (%)**, **Temp (C)**, **Runtime (min)** and **Error**. **Export** saves the list as an Excel file.

Every scan stores one reading for each device, also when the device does not answer. Readings older than **Max days logs** are deleted at the end of each scheduled scan.

## Trends

Pick the **Period**: a single date-range field, limited to the dates that have readings. Then pick one or more **Devices** among those with readings in that period. The page draws four line charts with one line for each device: **Battery (%)**, **Input Voltage (V)**, **Load (%)** and **Temperature (C)**. Charts can be zoomed and panned. Offline readings are left out.

## Alerts

After each scan the module checks the reading against the thresholds of the cluster settings. If at least one notifier is selected in the settings, it sends one notification that lists the alerts found:

| Condition | Severity |
|-----------|----------|
| Battery charge at or below **Default Shutdown Battery Threshold (%)** | Error |
| Battery charge at or below **Default Battery Low Threshold (%)** (and above the shutdown threshold) | Warning |
| Runtime reported by the UPS above 0 and at or below **Default Shutdown Time Threshold (minutes)** | Error |
| Status **Critical** | Error |
| Status **On Battery** | Warning |
| No reading from the device for two scans in a row | Error |

The notification reports device, status, battery charge and runtime. Its severity is Error when at least one alert is an error, otherwise Warning.

- A notification is sent when the alerts change, not at every scan: when the UPS goes on battery, when the charge then drops below a threshold, and so on. While nothing changes no further notification is sent.
- When no alert is active any more, one **back to normal** notification closes the episode.
- A single scan without a reading sends nothing: SNMP runs over UDP and one lost answer is common. The alert starts at the second failed scan in a row, so with the default schedule after about 10 minutes.
- No notification is sent while the state is **Unknown**.

## Settings

Settings are separate for each cluster.

<Collapse title="Show all settings" kind="settings">

| Setting | Default | Purpose |
|---------|---------|---------|
| **Enabled schedulation** | off | Master on/off switch for the scheduled scan |
| **Cron Schedule** | `*/5 * * * *` [<Mdi name="open-in-new" />](https://crontab.guru/#*/5_*_*_*_*) | When the scheduled scan runs |
| **Max days logs** | 30 | How many days of historical readings to retain |
| **Default Battery Low Threshold (%)** | 20 | Warning alert when the battery charge is at or below this level (0 to 100) |
| **Default Shutdown Battery Threshold (%)** | 10 | Error alert when the battery charge is at or below this level (0 to 100). When the UPS also runs on battery, the device status becomes **Critical** |
| **Default Shutdown Time Threshold (minutes)** | 5 | Error alert when the estimated runtime is at or below this value (1 to 60) |
| **Notifier** | - | [Notifier](../../configuration/admin-area/notifier/) configurations that receive the alerts. With none selected no alert is sent |

</Collapse>
