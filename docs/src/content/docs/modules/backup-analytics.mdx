## Sections

- **Overview**: introduction to the module and its dashboard widgets
- **Backups**: backup history collected by the scans, one row per guest and backup run. The columns are start, end, duration, size, transfer speed, status, node, storage and error. Failed rows are highlighted. On each row, **Show VM log** opens the log of that guest and **Show Job log** opens the log of the whole backup task. See [Collecting data](#collecting-data) for the scans and the toolbar actions
- **Scheduled**: configured backup jobs with schedule, target storage and selection
- **Unprotected Guests**: guests (templates excluded) whose ID is not listed in any enabled backup job
- **Unprotected Disks**: disks excluded from backup (e.g. `backup=0`)
- **Backup in line**: backup files currently on the storages, grouped by storage and VM, with size, date, format, verified/encrypted flags
- **Trends**: line charts of backup **Size**, **Speed** and **Duration** over time, one line per guest. Choose the **Period**, then the **Storages**, then the **VM / CT** to plot. **Period** is a single date range field, limited to the dates for which data exists

:::caution[Unprotected Guests: how coverage is evaluated]
The page compares only the guest IDs listed explicitly in the enabled backup jobs. It ignores a job that selects guests by pool, so the guests of that job are listed as unprotected. The page is empty when an enabled job is set to back up all guests, and also when no enabled job lists guests by ID.
:::

## Collecting data

**Backups**, **Trends** and the dashboard widgets work on data that a scan copies from Proxmox VE into the module database. **Scheduled**, **Unprotected Guests**, **Unprotected Disks** and **Backup in line** read the cluster live and need no scan.

A scan reads the `vzdump` tasks of every online node together with their logs (the first 10000 lines of each). It stores the tasks that are not in the database yet. It then deletes the records older than **Max days logs**.

Toolbar of the **Backups** page:

| Action | What it does |
|--------|--------------|
| **Scan** | Starts a scan immediately in the background. Progress and log are in the global Task Tracker |
| **Delete all data** | After confirmation, deletes every collected record of the cluster from the module database. Backups on the Proxmox VE storages are not touched |
| **Refresh** | Reloads the grid |
| **Export** | Downloads the grid as an Excel file |

The toolbar also shows the state of the schedule configured in the settings.

## Widgets

| Widget | Content |
|--------|---------|
| **Status** | Backup status |
| **Size** | Backup size |
| **Check** | Failed backups per guest in the last days |
| **Info** | Backup statistics |
| **Daily Status** <Tag kind="ee" /> | Successful and failed backups per day (last 14 days) |

The **Check** widget has one widget setting, **Days to analyze** (default 60). It covers only the clusters where **Enabled schedulation** is on. Otherwise it shows "Module not configured!".

## Settings

| Setting | Default | Purpose |
|---------|---------|---------|
| **Enabled schedulation** | off | Turns the scheduled scan on or off |
| **Cron Schedule** | `0 */1 * * *` [<Mdi name="open-in-new" />](https://crontab.guru/#0_*/1_*_*_*) | When the scheduled scan runs (default: hourly) |
| **Max days logs** | 30 | How many days of collected backup data to keep (minimum 1). Older records are deleted at the end of each scan |

## Permissions

Assign these to a role under [Security](../../configuration/admin-area/security/#permissions).

| Permission | Allows |
|------------|--------|
| **Backup Analytics** | Open the module and its **Overview** page |
| **Backups**, **Scheduled**, **Unprotected Guests**, **Unprotected Disks**, **Backup in line**, **Trends** | Open the page with that name (one permission per page) |
| **Status**, **Size**, **Check**, **Info**, **Daily Status** <Tag kind="ee" /> | Use the dashboard widget with that name (one permission per widget) |
| **Edit Settings** | Change the module settings |

**Scan** and **Delete all data** have no dedicated permission: they are available to every user who can open the **Backups** page.
