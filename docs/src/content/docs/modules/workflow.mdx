## Sections

- **Overview**: short description of the module
- **Workflows**: the list of workflow definitions of the current cluster. Open a definition to edit it in the designer. **Back to List** returns to the list. When you run a workflow from the designer, the page switches to the view of that run. **Back to editor** returns to the designer
- **History**: the list of workflow runs (instances). Open a run to see its status and the detail of each step. **Back to List** returns to the list. From a run you can open its definition in the designer and come back with **Back to View Instance**

Workflows belong to the cluster selected in the cluster picker. Definitions and runs of one cluster are not listed in another. The activities of a workflow always act on the cluster the workflow was created in.

## Requirements

- Configure the `Urls` setting of the application. The embedded designer calls the workflow engine of the same application at the first address listed there, under `/api/elsa`. Without `Urls` the application does not start.
- Expressions can be written in **C#** or **JavaScript**.
- The Proxmox VE user or API token of the cluster needs the privileges for the operations the workflows run. See [Proxmox VE Permissions](../workflow-activities/).

## Available Activities

The module adds 26 activities to the designer toolbox, next to the standard ones of Elsa Workflows. They are organised under **Proxmox VE** and **Admin**. The full list, with inputs and outputs, is in [Activities](../workflow-activities/).

## Permissions

The module defines these application permissions. All of them are included in the module administrator role.

| Permission | Description |
|------------|-------------|
| **Workflow** | Open the module and its **Overview** page |
| **Workflows**, **History** | Open the page with that name (one permission per page) |
| **Workflow: Read, Create, Edit, Delete, Export** | Workflow definitions |
| **Workflow: Execute Workflow** | Run a workflow |
| **History: Read, Export** | Workflow runs |
| **History: Delete** | Delete workflow runs |

**Persistence:** Workflow definitions and runtime state are stored in the `workflow_elsa` Postgres schema, separate from the cv4pve-admin schema.
