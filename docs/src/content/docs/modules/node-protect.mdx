- <Tag kind="ee" /> **Git**: commits of the local Git repository with author, size and changed files. See [Git destination](#git-destination). In the Community Edition the page shows that a subscription is required

## How a backup works

Node Protect connects over SSH to every online node of the cluster and packs the configured paths with `tar`. `tar` stays on the file system of each path and skips the files that cannot be read. Offline nodes are skipped.

A backup has two possible destinations: the [Folder destination](#folder-destination) and the [Git destination](#git-destination) (Enterprise Edition). The paths are the same for both destinations: one path per line in **Directory or file to backup**.

Both destinations follow the same schedule. With **Enabled schedulation** on, each destination that is itself enabled runs at the **Cron Schedule**.

## Folder destination

Each run creates a folder in the application data directory, named after the run time (`yyyy-MM-dd-HH-mm-ss`). The folder holds one archive per node, named `<node>-config.tar.gz`.

| Action | What it does |
|--------|--------------|
| **Backup** | Starts a backup immediately in the background. The button is disabled until the Folder destination is enabled in the settings |
| **Delete** | After confirmation, deletes the selected archives and their records |
| **Download** (per row) | Downloads the archive of that node |
| **Show log** (per row) | Opens the log of the backup of that node |
| **Refresh** | Reloads the grid |

**Retention:** the Folder setting **Number which should will keep** says how many runs to keep. After a run in which every node succeeded, only that number of newest runs is kept and the older ones are deleted. If the backup of at least one node fails, retention is not applied for that run. This way a good backup is never deleted to make room for an incomplete one.

## Git destination

<Tag kind="ee" /> Each run does three things, in this order:

1. It rebuilds the working copy of a local Git repository: one folder per node, plus the `.gitignore` from the settings.
2. It creates a commit named `auto-commit at` followed by the date.
3. It pushes the commit to the configured remote branch.

:::caution[The push is forced]
The remote branch is overwritten with the local history. Use a repository and a branch dedicated to Node Protect.
:::

The **Push** button is a split button, disabled until the Git destination is enabled. **Sync from remote** and **Open remote repository** appear only when **Remote Url** is set:

| Action | What it does |
|--------|--------------|
| **Push** | Runs backup, commit and push immediately in the background |
| **Reset** | After confirmation, deletes the local repository and starts an empty one. The remote is not touched until the next push |
| **Sync from remote** | After confirmation, deletes the local repository and clones the remote branch again |
| **Open remote repository** | Opens the **Remote Url** in a new browser tab |
| **Download** (per row) | Downloads the files of that commit as a `.tar.gz` archive |

Expanding a commit row lists the changed files with their status and path.

## Settings

<Collapse title="Show all settings" kind="settings">

**General**

**Enabled schedulation**

Turns the scheduled backup on or off

- **Default:** off

**Cron Schedule**

When the scheduled backup runs (default: 06:00 daily)

- **Default:** `0 6 * * *` [<Mdi name="open-in-new" />](https://crontab.guru/#0_6_*_*_*)

**Directory or file to backup**

Required. One path per line. Default: `/etc/.`, `/var/lib/pve-cluster/.`, `/var/lib/ceph/.`, `/var/spool/cron/crontabs`, `/root/.ssh`, `/root/scripts`, `/root/backup`, `/root/.bashrc`, `/root/.profile`. Edit to suit your node layout

- **Default:** preset list

**Folder** tab

| Setting | Default | Purpose |
|---------|---------|---------|
| **Enabled** | off | Enable local folder backup destination |
| **Number which should will keep** | 30 | Maximum number of past backups to retain in the folder (minimum 1) |

**Git** tab <Tag kind="ee" />

| Setting | Default | Purpose |
|---------|---------|---------|
| **Enabled** | off | Enable the Git destination: each scheduled backup commits and pushes the protected files |
| **Remote Url** | - | Required. URL of the remote Git repository |
| **Remote Branch Name** | - | Required. Branch of the remote that receives the commits |
| **Display Name** / **Email** | - | Required. Author identity recorded on every commit |
| **Username** / **Password** | - | Required. Credentials used to authenticate with the remote |
| **.gitignore file** | `*/etc/pve/nodes/*/lrm_status`<br />`*/etc/pve/.rrd` | Content of the `.gitignore` written to the repository: paths matching these patterns are not committed |

</Collapse>

## Permissions

Assign these to a role under [Security](../../configuration/admin-area/security/#permissions).

| Permission | Allows |
|------------|--------|
| **Node Protect** | Open the module and its **Overview** page |
| **Folder**, **Git** | Open the page with that name (one permission per page) |
| **Folder Size**, **Git Size** <Tag kind="ee" />, **Daily Status** <Tag kind="ee" /> | Use the dashboard widget with that name (one permission per widget) |
| **Edit Settings** | Change the module settings |

The actions of the pages (**Backup**, **Delete**, **Download**, **Push**, **Reset**, **Sync from remote**) have no dedicated permission: they are available to every user who can open the page.
