## Sections

- **Overview**: short description of the module
- **Dashboard**: one status card for each enabled UPS device
- **Devices**: UPS device configuration, on-demand scan, connection test and reading history
- **Trends**: charts of the readings over time

Devices, readings and settings are separate for each cluster.

:::caution[Monitoring and alerts only]
The module reads the UPS and sends notifications. It does not shut down or stop nodes, VMs or containers: the settings named **Shutdown ... Threshold** are alert thresholds.
:::

## Requirements

- **SNMP v2c** connection: the UPS (or its network card) must answer SNMP v2c queries from the cv4pve-admin server on the configured port (default UDP 161) with the configured community.
- **SNMP v3** connection: the same, with a user of the device instead of the community. See [SNMP v3](#snmp-v3).
- **NUT** connection: a NUT server (Network UPS Tools, `upsd`) must accept connections from the cv4pve-admin server on the configured port (default TCP 3493). See [NUT connection](#nut-connection).
- **Host** is an IP address or a host name that the cv4pve-admin server can resolve.
- A request that gets no answer within 3 seconds is treated as a failed reading.

## Dashboard

At the top, four counters: devices **Online**, **On Battery** (with those on low battery), **Critical** and **Offline** (with those never read or in an unknown state).

Below, each enabled device has a card. The devices that need attention come first: critical, on battery, low battery, offline, then the others by name. A card shows:

- name and status badge, manufacturer and model, detected brand, location. The left edge of the card has the colour of the status
- a notice while the device runs on battery (**On battery for** and how long) or does not answer (**No answer for** and how long)
- **Battery** with its value, a bar and a small chart of the last three hours: red up to 20%, yellow up to 50%, green above
- **Load** with its value, a bar and a small chart of the last three hours: green below 50%, yellow from 50%, red from 80%
- **Input** and **Output** voltage, **Runtime** and **Temperature**
- the time of the last reading

A value the device does not give is shown as `-`. An offline device keeps its last values, dimmed.

The cards show the last reading. An open page is updated every few seconds, at once when the status of a device changes.

### Status values

| Status | Meaning |
|--------|---------|
| **Online** | Output supplied by mains power |
| **On Battery** | Output supplied by the battery, charge above the shutdown battery threshold |
| **Low Battery** | The UPS reports a low battery while not running on battery |
| **Critical** | The UPS reports a depleted battery. Or it runs on battery and either reports a low battery or has a charge at or below the shutdown battery threshold |
| **Offline** | The device gave no reading for the number of readings in a row set in **Unreachable after**: it did not answer, its name could not be resolved, or it has none of the values of the selected profile. The reading history shows the reason |
| **Unknown** | The device answered but its state is none of the above, for example bypass or voltage regulation active |

## Devices

The grid lists the devices of the cluster with **Enabled**, **Name**, **Host**, **Port**, **Connection**, **Detected Brand**, **Last Status**, **Last Scan**, **Location** and **Managed Nodes** (**All** or the number of nodes). Click the name of a device to edit it.

Each UPS device is configured with:

| Field | Description |
|-------|-------------|
| **Enabled** | Read the device and show it in the Dashboard (default: on) |
| **Name** | Friendly name for the UPS device (required) |
| **Connection** | **SNMP v2c** (default), **SNMP v3** or **NUT (Network UPS Tools)**. Changing it also changes the port, while the port is still the default of the connection left |
| **Host** | IP address or host name of the UPS SNMP agent, or of the NUT server (required) |
| **Port** | Default: 161 for SNMP v2c and v3, 3493 for NUT |
| **Community** | SNMP v2c only: community string (default: `public`) |
| **User**, **Security level**, **Authentication**, **Privacy** and their passwords | SNMP v3 only: see [SNMP v3](#snmp-v3) |
| **Profile** | SNMP v2c and v3: device profile (`auto` = detect the brand from the device, or pick one explicitly) |
| **UPS name** | NUT only: the name of the UPS on the NUT server (default: `ups`) |
| **Location** | Physical location label |
| **Description** | Free-text notes |
| **Managed Nodes** | Proxmox nodes powered by this UPS (empty = all nodes): informational |
| **Identification** | Manufacturer, Model, Firmware Version, Serial Number: filled from the device with **Retrieve Info**, or typed by hand |

**Retrieve Info** reads the identification values from the device (with the selected profile for SNMP, from the NUT server for NUT) and writes them in the four fields. It needs the **Host** to be filled in. The values are saved with the device.

Per-device actions (select a row first):

- **Scan**: reads the selected device now, also when the monitoring is off. The result appears in the grid and is always stored in the reading history, also a single missed answer
- **Test Connection**: queries the device. When it answers, a dialog shows what the device declares (the SNMP system description, or the version of the NUT server), the profile or NUT driver detected and one row for each value: where it is read from (an OID or a NUT variable) and the value received, or **Missing** when the device does not have it. The power source and the battery state are shown with their meaning next to the number. A warning says which alert thresholds cannot fire because the device has no charge or no runtime value. When the device does not answer, a message gives the reason: no answer within 3 seconds, or a host name that cannot be resolved. A missing answer usually means a wrong address, port or community, or SNMP v2c turned off on the device

### Profiles

With `auto` the profile is chosen by asking the device which values it has, and shown in **Detected Brand**. The profile found is used for the following readings and searched again only when the device stops giving its values:

1. the profile of the manufacturer the device declares (its SNMP object identifier), when the device has the values of that brand;
2. otherwise **Generic RFC 1628**, the standard UPS MIB, when the device has it. It is the case of most third-party SNMP cards;
3. otherwise any other verified brand whose values the device has.

The text of the system description is not used: it is written by the SNMP card and often names no brand. When the device answers but has none of these values, the reading and **Test Connection** fail with a message saying so: the device is not a UPS, or its SNMP card does not publish the values.

With a profile picked explicitly, a device that has none of its main values (battery status, charge, output source) gives no reading, with a message that says the profile is probably the wrong one.

A verified profile is written from the published definitions (MIB) of the standard or of the manufacturer: every value, its unit and the meaning of each state. Verified profiles have been tried against a simulator, not on a real device of each brand: if the readings look wrong, run **Test Connection** and compare the values with the display of the device, or select **Generic RFC 1628**.

| Profile | Source | Notes |
|---|---|---|
| **Generic RFC 1628** | Standard UPS MIB | The standard has no serial number |
| **APC / Schneider Electric** | PowerNet MIB | Self-test, boost, trim, ECO and standby states count as on mains. No manufacturer value |
| **CyberPower** | CPS MIB | No manufacturer value |
| **Delta** | DeltaUPS MIB | No serial number |
| **Eaton / Powerware** | XUPS MIB | No battery-low state and no serial number |
| **HPE / HP** | CPQPOWER MIB | No battery-low state and no serial number. The MIB does not give the unit of the battery voltage: tenths of volt are assumed |
| **Mach Power / NetAgent / Ablerex / Tecnoware** | XPPC MIB (NetAgent cards) | No manufacturer value, no output power |
| **MGE / Pulsar** | MG-SNMP-UPS MIB | The MIB says "on battery: yes or no": bypass is not told apart from mains. The MIB gives no units: tenths of volt and of hertz, runtime in seconds are assumed |
| **Riello** | RIELLOUPS MIB | Same structure as the standard. The MIB gives no units: those of the standard are assumed. No serial number |
| **Tripp Lite** | TRIPPLITE-PRODUCTS MIB | Reads the first device of the card |

A value the brand does not define is read from the standard MIB, when the device has it.

These profiles are **not verified**: `auto` never chooses them, they work only when picked by hand, and the editor shows a note when one is selected.

| Profile | State |
|---|---|
| **Socomec** | Values taken from the Network UPS Tools driver for Net Vision cards, not from a Socomec MIB. Only the mains state is known: on battery the status is **Unknown** |
| **Huawei** | Values taken from the Network UPS Tools driver, not from a Huawei MIB |
| **Chloride**, **GE / General Electric**, **Phoenix Contact** | No definition found to check them against |

A brand that is not in the lists is read with **Generic RFC 1628**, which most network cards publish. A device saved with a profile that is no longer in the lists is read as `auto`.

A state of the device that is neither mains nor battery (bypass, output off, a state the profile does not know) gives the status **Unknown** and no alert.

### SNMP v3

SNMP v2c sends the community in clear text and does not authenticate who asks. SNMP v3 uses a user of the device, with authentication and, if wanted, encryption. The profiles and the values read are the same as with v2c.

| Field | Description |
|---|---|
| **User** | The SNMP v3 user configured on the device |
| **Security level** | **Authentication and privacy** (default): requests are authenticated and encrypted. **Authentication only**: authenticated, the values travel in clear text |
| **Authentication** and its password | SHA-256 (default), SHA-384, SHA-512, SHA-1 or MD5. The password has at least 8 characters |
| **Privacy** and its password | AES-128 (default), AES-192 or AES-256. Shown with **Authentication and privacy**. The password has at least 8 characters |

- The algorithms and the passwords must be the ones set for that user on the device.
- SHA-1 and MD5 are weak: the editor says so. Use them only when the device offers nothing else.
- The passwords are stored encrypted.
- The community of v2c and the settings of v3 are both kept: changing the connection and coming back loses nothing.

When the reading fails the message says why: user unknown to the device, authentication failed (password or algorithm), security level not accepted by the device or not allowed to that user. A wrong privacy password or algorithm usually gives no answer at all, because the device drops what it cannot decrypt: the message for a missing answer mentions it.

Tried against a Net-SNMP agent: every authentication algorithm with AES-128, SHA-256 with AES-192 and AES-256, and authentication only. Not tried on the network card of a real UPS. AES-192 and AES-256 have more than one variant among manufacturers: if a device refuses them, use AES-128. 3DES and DES are not available.

### NUT connection

For a UPS without a network card, connected by USB or serial cable to another machine (a server, a NAS, a small board) where a [NUT](https://networkupstools.org/) server runs. cv4pve-admin connects to that server over the network and reads the values of the UPS. It only reads: it never registers as a monitor of the UPS and never sends it a command.

What the NUT server needs:

- to listen on the network, not only on the local address: a `LISTEN` line with an address the cv4pve-admin server can reach in `upsd.conf`, and the port (3493 by default) open on its firewall;
- the name of the UPS, which is the name of its section in `ups.conf`, written in **UPS name**.

No user is needed: a NUT server gives the values of a UPS to any client it accepts connections from.

There are no profiles: the variable names are the same for every brand and driver. **Detected Brand** shows `NUT` followed by the driver in use on the server.

| Value | NUT variable |
|---|---|
| Power source and battery low | `ups.status`: `OL` on mains, `OB` on battery, `BYPASS` bypass, `LB` battery low. The other flags are ignored |
| Battery charge | `battery.charge` |
| Runtime | `battery.runtime`, which is in seconds, shown in minutes |
| Temperature | `ups.temperature`, or `battery.temperature` |
| Battery, input and output voltage | `battery.voltage`, `input.voltage`, `output.voltage` |
| Load | `ups.load` |
| Manufacturer, model, firmware, serial number | `device.mfr` or `ups.mfr`, `device.model` or `ups.model`, `ups.firmware`, `device.serial` or `ups.serial` |

A value the driver does not give is missing, not zero: **Test Connection** shows which ones.

The reading fails, with a message that says what to check, when the server does not answer within 3 seconds or refuses the connection, when it has no UPS with that name, when its driver is not connected, and when its data are stale. Stale data mean that the driver has stopped updating: the server would go on giving the last good values, so they are treated as no reading, never as "on mains".

Tried against a real NUT server with a simulated UPS (the `dummy-ups` driver), not with a UPS on a cable.

### Reading history

Expand a device row to see its readings, newest first: **Timestamp**, **Status**, **Battery (%)**, **Input (V)**, **Load (%)**, **Temp (C)**, **Runtime (min)** and **Error**. **Export** saves the list as an Excel file.

The devices are read much more often than the history is written. A reading is stored:

- at every reading while the UPS runs on battery (status **On Battery** or **Critical**);
- whenever the status changes;
- otherwise once a minute.

Readings older than **Max days logs** are deleted once a day.

## Trends

Pick the **Period**: a single date-range field, limited to the dates that have readings. Then pick one or more **Devices** among those with readings in that period. The page draws four line charts with one line for each device: **Battery (%)**, **Input Voltage (V)**, **Load (%)** and **Temperature (C)**. Charts can be zoomed and panned. Offline readings are left out.

## Alerts

After each reading the module checks the values against the thresholds of the cluster settings. If at least one notifier is selected in the settings, it sends one notification that lists the alerts found:

| Condition | Severity |
|-----------|----------|
| Battery charge at or below **Default Shutdown Battery Threshold (%)** | Error |
| Battery charge at or below **Default Battery Low Threshold (%)** (and above the shutdown threshold) | Warning |
| Runtime reported by the UPS above 0 and at or below **Default Shutdown Time Threshold (minutes)** | Error |
| Status **Critical** | Error |
| Status **On Battery** | Warning |
| No reading from the device for the number of readings in a row set in **Unreachable after** | Error |

The notification reports device, status, battery charge and runtime. Its severity is Error when at least one alert is an error, otherwise Warning.

- A notification is sent when the alerts change, not at every reading: when the UPS goes on battery, when the charge then drops below a threshold, and so on. While nothing changes no further notification is sent.
- When no alert is active any more, one **back to normal** notification closes the episode.
- A single missed reading changes nothing: SNMP runs over UDP and one lost answer is common. The device keeps its status until the readings missed in a row reach **Unreachable after**, then it becomes **Offline** and the alert is sent: with the default values after about a minute and a half.
- A UPS on battery is read at the shorter interval, also when it stops answering after going on battery.
- No notification is sent while the state is **Unknown**.

## Settings

Settings are separate for each cluster.

A change of the settings, a new device or an edited one is applied within a few seconds, without restarting the application.

:::caution
The readings run inside the application. Run a single instance of it: two instances reading the same devices would both send the alerts.
:::

<Collapse title="Show all settings" kind="settings">

| Setting | Default | Purpose |
|---------|---------|---------|
| **Monitoring enabled** | off | Master on/off switch: with it off the devices are read only with **Scan** |
| **Reading interval (seconds)** | 30 | How often each device is read (10 to 3600) |
| **Reading interval on battery (seconds)** | 8 | How often a device is read while it runs on battery (5 to 300) |
| **Unreachable after (missed readings)** | 3 | Readings missed in a row before the device becomes **Offline** and the alert is sent (1 to 20) |
| **Max days logs** | 30 | How many days of historical readings to retain |
| **Default Battery Low Threshold (%)** | 20 | Warning alert when the battery charge is at or below this level (0 to 100) |
| **Default Shutdown Battery Threshold (%)** | 10 | Error alert when the battery charge is at or below this level (0 to 100). When the UPS also runs on battery, the device status becomes **Critical** |
| **Default Shutdown Time Threshold (minutes)** | 5 | Error alert when the estimated runtime is at or below this value (1 to 60) |
| **Notifier** | - | [Notifier](../../configuration/admin-area/notifier/) configurations that receive the alerts. With none selected no alert is sent |

</Collapse>
