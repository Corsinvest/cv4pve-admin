## Sections

- **Overview**: short description of the module
- **Status**: grid with one row for each block device of every running QEMU VM of the cluster, grouped by **Node** and then by **VmId**

The module has no settings. It has two permissions: **VM Performance** gives access to the module and to its **Overview** page, **Status** gives access to the **Status** page.

## Status

| Column | Content |
|--------|---------|
| **Status** | Status icon of the VM |
| **Device** | Block device name as reported by QEMU |
| **Read Bytes**, **Write Bytes** | Cumulative bytes read and written (QEMU counters `rd_bytes` and `wr_bytes`) |
| **Read IOPS**, **Write IOPS** | Cumulative number of read and write operations (QEMU counters `rd_operations` and `wr_operations`) |
| **Read Bytes Sec**, **Write Bytes Sec** | Bytes per second |
| **Read IOPS Sec**, **Write IOPS Sec** | Operations per second |
| **Node**, **VmId**, **Name** | Hidden by default, can be shown from the column picker |

The toolbar has **Refresh** and **Export** (Excel file with the list). The grid can be filtered, sorted and regrouped.

Data is read when the page opens and each time you click **Refresh**: there is no automatic refresh. Each read runs the QEMU Monitor command `info blockstats` on every running VM, so it takes longer on clusters with many VMs.

**How rates are computed:** The sample taken when the page opens is the baseline. At every **Refresh** the per-second columns are computed as `(current counter - baseline counter) / seconds since the baseline`, so they are the average rate since the page was opened. The cumulative columns keep showing the baseline values. Until the first **Refresh** the per-second columns are 0. Reopen the page to start from a new baseline.

## Requirements

The Proxmox VE user or API token of the cluster must be allowed to use the QEMU Monitor of the VMs.
