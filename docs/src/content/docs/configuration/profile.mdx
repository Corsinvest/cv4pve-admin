## Access

Click your avatar in the top right corner of the application to open the profile menu. It contains:

| Entry | Description |
|-------|-------------|
| **Dark** / **Light** | Switches the theme between light and dark. The choice is remembered in the browser, so it can differ from one browser to another. |
| **Profile** | Opens the pages described below. |
| **Admin Area** | Opens the [Admin Area](../admin-area/). |
| **Sign Out** | Ends the session. |

## Preferences

**Language** sets the language of the user interface for your account. Select it and click **Save changes**: the page reloads in the new language.

English is currently the only language available.

## Password

Enter the **Old Password**, the **New Password** and repeat it in **Confirm Password**, then click **Update password**. After the confirmation the page reloads and you stay signed in.

The new password must satisfy the password policy of the installation. By default: at least 6 characters, with at least one digit, one lowercase letter, one uppercase letter and one special character. An administrator can change the policy in [appsettings.extra.json](../appsettings-extra/#security-settings).

**Forgotten password:** If you cannot log in, use **Forgot password?** on the login page to receive a reset link by email. This requires the SMTP server to be configured in [General Settings](../admin-area/general-settings/#smtp-configuration). As an alternative, ask an administrator to reset the password with the [CLI](../../cli/).

## Two-factor authentication (2FA)<Tag kind="ee" />

Adds a second step to the login: a 6-digit code generated by an authenticator app (TOTP).

The page shows the current state: **2FA is not enabled** or **2FA is active**.

### Enable 2FA

1. Click **Enable 2FA**.
2. Scan the QR code with your authenticator app, or type the **Manual entry key** shown under it.
3. Enter the 6-digit code generated by the app and click **Verify & Enable 2FA**.
4. Ten **recovery codes** are shown. Save them in a safe place: use **Download Codes** to get them as a text file, then click **I've Saved the Codes**.

Recovery codes are meant for the case where the authenticator device is not available. Each code can be used only once.

### Logging in with 2FA

After user name and password, the login asks for the authenticator code. A wrong code can be typed again on the same page, until the account is locked for too many failed attempts.

If the authenticator device is not available, click **log in with a recovery code** on the same page and enter one of the saved recovery codes. The code is consumed: it cannot be used a second time.

**Remember Machine** skips the code on that browser for the following logins. The 2FA page shows a remembered browser as **This browser is remembered for 30 days**. Its **Forget** button makes the login ask for the code again.

### Managing 2FA

| Action | Description |
|--------|-------------|
| **Generate Recovery Codes** | Creates ten new recovery codes and shows them once, with **Download Codes**. All the previous codes stop working immediately. |
| **Reset Authenticator** | Turns 2FA off and starts the setup again with a new QR code: the current entry in your authenticator app stops working. Use it to move 2FA to another device. |
| **Disable 2FA** | Turns 2FA off. Requires the 6-digit code from the authenticator app or one of the recovery codes, plus a confirmation. |
| **Forget** | Removes the "remembered browser" state of the current browser. |

Turning 2FA off sends you an email, so a change you did not make does not go unnoticed.

**Lost device and recovery codes:** ask an administrator to use **Disable 2FA** in [Security](../admin-area/security/#users), or use the [CLI](../../cli/) on the server. A password reset does not turn 2FA off.

When three or fewer recovery codes are left, the page shows a warning with a **Generate new codes** button.

:::caution[Reset Authenticator]
After **Reset Authenticator** 2FA stays off until the new setup is completed. If you close the setup before entering the code, the account is protected by the password only.
:::

## Audit Logs<Tag kind="ee" />

The audit log filtered on your account: logins and the actions you performed. It has the same columns and details as the administrator's [Audit Logs](../admin-area/security/#audit-logs).

## Active Sessions

Lists the browser sessions currently connected with your account: **UserName**, **Login**, **Ip Address**, **Device**, **Platform**, **Browser**, **Current Page** and **Last Activity**. Use it to check that every session is one of yours.

<Tag kind="ee" /> Select one or more sessions and use **Force logout** to terminate them, or **Send Message** to send them a notification.

In the Community Edition the list is read-only.
