## Sections

- **Overview**: introduction to the module and its dashboard widget
- **Scans**: live grid of every running VM/CT, with its current scan status (InScan / Ok / InError / Cancelled), its available updates (Normal / Security) and its reboot required flag. From this page you start a new scan and download the report as PDF or Excel. See [Scanning](#scanning)

## Scanning

A scan covers the guests that are running when it starts: stopped guests are not listed. The module runs a search script inside each guest: the Linux script or the Windows script, depending on the guest. From the script it reads back whether normal updates, security updates or a reboot are pending. The default Linux script recognises the common package managers (`apt`, `dnf`, `yum`, `zypper`, `apk`, `pacman` and others).

| Action | What it does |
|--------|--------------|
| **Scan** | Starts a scan immediately in the background. The grid updates while the guests are scanned |
| **Download** | Split button: downloads the current result as **PDF** or **Excel**. Disabled until a result exists |

The scan appears in the global Task Tracker and can be cancelled from there. When you cancel, the guests not scanned yet are marked `Cancelled`.

A guest that fails is marked `InError`, with the message in the **Error** column. The scan continues with the other guests.

**No scan history:** Only the result of the last scan is available. It is kept in the application cache for 8 hours and is not stored in the database. To see data again, run a new scan or wait for the scheduled one.

## Settings

<Collapse title="Show all settings" kind="settings">

**Enabled schedulation**

Turns the scheduled scan on or off

- **Default:** off

**Cron Schedule**

When the scheduled scan runs (default: every 12 hours)

- **Default:** `0 */12 * * *` [<Mdi name="open-in-new" />](https://crontab.guru/#0_*/12_*_*_*)

**Max parallel requests**

Maximum number of VM/CT scanned at the same time (1 = sequential, range 1-50). Lower it if the nodes get overloaded during a scan

- **Default:** 5

**Script Windows Search Update**

Script run inside Windows guests to detect updates. The refresh button restores the default script

- **Default:** bundled PowerShell

**Script Linux Search Update**

Script run inside Linux guests / LXC to detect updates. The refresh button restores the default script

- **Default:** bundled bash

**Notifier**

[Notifier](../../configuration/admin-area/notifier/) configurations that receive the PDF report at the end of a scan. The notification is sent only when at least one guest has pending updates or needs a reboot

</Collapse>

## Permissions

Assign these to a role under [Security](../../configuration/admin-area/security/#permissions).

| Permission | Allows |
|------------|--------|
| **Update Manager** | Open the module and its **Overview** page |
| **Scans** | Open the page with that name (one permission per page) |
| **Status** | Use the dashboard widget |
| **Edit Settings** | Change the module settings |

**Scan** and **Download** have no dedicated permission: they are available to every user who can open the **Scans** page.

<RequirementsSsh />

:::note[Guest requirements]
QEMU VMs must have the QEMU Guest Agent enabled and responding. Windows guests are scanned only when their OS type is `win10` or `win11`. LXC containers need no agent.
:::
