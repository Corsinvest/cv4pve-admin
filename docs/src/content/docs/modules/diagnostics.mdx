In the menus of the application the module is named **Diagnostic**.

Automated health checks and infrastructure diagnostics for Proxmox VE, built on the [`cv4pve-diag`](https://github.com/Corsinvest/cv4pve-diag) library. Each issue is reported with a gravity (`Info` / `Warning` / `Critical`), a context (cluster, node, storage, qemu, lxc) and a sub-context that pinpoints what to look at.

## Sections

- **Overview**: introduction to the module and its dashboard widgets
- **Scans**: the history of scans. Expand a row to see the scan detail: an **Issues** tab with the detail of each issue, and a **Compliance** tab <Tag kind="ee" /> with the findings grouped by standard and control. From this page you also download the report as PDF or Excel and start a new on-demand scan. Both reports open with a cover page: report information and a table of contents. In the PDF the table of contents has page numbers, is clickable and is listed in the bookmarks panel of the viewer
- **Ignored Issues**: the issues hidden from the active results (they are still shown in the report's Ignored section). See [Ignored issues](#ignored-issues)

## Scans

The grid lists the stored scans with the number of **Info**, **Warning** and **Critical** issues, start, end and duration. Ignored issues are not counted.

| Action | What it does |
|--------|--------------|
| **Scan** | Starts a scan immediately in the background. Progress and log are in the global Task Tracker |
| **Download** | Split button: downloads the report of the selected scan as **PDF** or **Excel**. Disabled until a scan is selected |
| **Delete** | After confirmation, deletes the selected scan |
| **Refresh** | Reloads the grid |

Expanding a scan shows two tabs: **Issues** and **Compliance** <Tag kind="ee" />. The **Issues** tab lists gravity, code, resource id (a link that opens the resource), context, sub-context and description of each issue. The **Ignore Issue** button on an issue row adds it to the ignored issues.

Two things happen at the end of every scan, scheduled or started by hand. The oldest scans beyond the **Number which should will keep** setting are deleted, and the notification is sent (see [Settings](#settings)).

## Ignored issues

An ignored issue is a rule with **Id Resource**, **Gravity**, **Context**, **Sub Context** and **Description**. It is created with the **Ignore Issue** button of a scan, which copies the values of that issue. On the **Ignored Issues** page click the **Id Resource** of a row to edit the rule, or select rows and use **Delete** to remove them.

The rules are applied when a scan runs: an issue is marked as ignored when its resource id, sub-context and description contain the text of the rule. Changing the list does not change the scans already stored.

## Compliance reports<Tag kind="ee" />

Each check in the `cv4pve-diag` library declares which normative controls it covers, and the Enterprise PDF and Excel reports add one section per standard. The standards covered, the layout of those sections and the limits of the mapping are in [Compliance Reports](../diagnostics-compliance/).

## Settings

The settings of the module (9 groups, from the general options to the thresholds and the snapshot, backup and CVE checks) are in [Settings](../diagnostics-settings/).

## Widgets

| Widget | Content |
|--------|---------|
| **Status** | Diagnostic status, with the date of the last scan |
| **Check** | Critical issues of the last scan of each cluster, grouped by resource, with a link to the scan |

**Check** covers only the clusters where **Enabled schedulation** is on, otherwise it shows "Module not configured!".

## Permissions

Assign these to a role under [Security](../../configuration/admin-area/security/#permissions).

| Permission | Allows |
|------------|--------|
| **Diagnostic** | Open the module and its **Overview** page |
| **Scans**, **Ignored Issues** | Open the page with that name (one permission per page) |
| **Status**, **Check** | Use the dashboard widget with that name (one permission per widget) |
| **Edit Settings** | Change the module settings |

**Scan**, **Download**, **Delete** and **Ignore Issue** have no dedicated permission: they are available to every user who can open the page.
